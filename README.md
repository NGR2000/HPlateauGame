# 実際のデータと創作の世界

このプロジェクトでは、実際の地形を土台にした「創作の世界」を中心に開発します。
車で走る・気球から眺める体験から始め、建物を置いて街をつくる遊びへ育てます。
ゲーム名は未定です。

## 遊ぶ

[ホームを開く](https://ngr2000.github.io/HPlateauGame/)

- **実際のデータの世界**：これまでの気球ゲーム。エリア・風・開始時刻・離陸地点を選んで飛行します。実験機能は開発環境専用です。
- **創作の世界**：佐賀・嘉瀬川の既定エリア・風・出発地点を使うチェイスモード。車を操作し、チームのパイロットと周囲の5機が気球を飛ばします。

創作側は実地形を草地として表現した架空の街です。実在の街並みを再現するものではありません。
初期の街には、離陸広場からターゲットへ続く通り、住宅・店舗、駅前広場、公園、スポーツ施設を配置しています。通りの横には合流できる空間を残し、車は道を外れて自由に走れます。建物の本体には進入できません。
街の外縁には東京タワーと、増上寺の参考画像から着想した山門・参道・本堂を配置しています。チェイス競技では、気球（投下後はマーカー）が読み込み済みの地形範囲外へ出ると終了します。

車の操作：W/S または上下キーで加減速、A/D または左右キーでハンドル。チェイスモードはGameTargetに合わせ、Vで「進行方向／気球を見る」、Oで「俯瞰／運転に戻る」を切り替えます。創作の世界ではBで車を中心に真上から見る視点へ切り替えます。真上でも運転でき、もう一度Bを押すと元の視点へ戻ります。
創作側は自分のチームの離陸地点にある車の視点から始まります。自分のチームのパイロットが地上から離陸し、ほかの5機は上空を飛びます。
Oキーまたは「自分のチームを俯瞰」ボタンで、自分の気球とチェイスカーを収める範囲を見渡せます。他の5機は画角の自動調整には含めず、景色として飛びます。俯瞰中はホイール・ピンチで拡大縮小でき、引いて周囲の気球も眺められます。運転に戻ってから俯瞰を開き直すと、ズームを初期範囲へ戻します。Oで運転に戻ると見る方向を保ち、Vを押すと運転に戻って見る方向を切り替えます。
運転カメラは車の後方14m・高さ6mを基準に地面へ潜らないよう補正します。停車中はドラッグで見回し、ホイール・ピンチでズームできます。発進や視点切替で通常のカメラに戻ります。
チェイスモードのバーナー・排気音は車との距離（高度差を含む）で小さくなり、300m以上では聞こえません。創作側は他チームの気球も対象です。俯瞰に切り替えても、音を聞く位置は車のままです。
スマホ・タブレットでは、両方の世界のチェイスモードに前進・ブレーキ／後退・左右ハンドルのタッチボタンが表示されます。前進とハンドルは同時に長押しできます。指を離すと入力が解除され、アクセルを離した車は自然減速します。
景色を広く見せるため、普段は左右下の半透明の運転ボタンと右上の「☰ メニュー」だけを表示します。メニューの「真上」はBキーと同じ切り替えです。真上視点は北が上の平行投影で、高さによる水平位置のずれがなく、ホイール・ピンチで拡大縮小できます。視点・俯瞰・一時停止・計器・世界名・ホームへの移動はメニュー内にまとめています。視点を選ぶとメニューは自動で閉じます。

創作側の1号車には、提供されたBlenderモデル `sky_chase_car.blend` を使用します。
自分のチームの気球は提供モデル `MV56b_hot_air_balloon.blend` を使用します。俯瞰・真上のときだけ水色の「気球」と黄色の「車」の名札が付きます。運転中・気球を見る視点では名札と補助線を隠します。名札はスマホ・PCや視点の距離によらず一定の小さいサイズで表示します。
ほかの5機は色と巡航高度を変えています。回収・スコアの対象は従来どおり自分のチームのマーカーです。
一時停止と時間加速は全機に反映します。
元データとブラウザ用GLB、再変換手順は [提供アセット](game/prototype/assets/README.md) に保存しています。

## 街を作り変える

ホームの主要ボタンは従来どおりです。「創作の世界」の下の小さな「街を作り変える」リンクから編集画面を開きます。

- 提供された東京駅・東京タワー・スポーツ施設・ビルと、住宅・店舗・倉庫・お寺・公園・広場・通り・木を配置できます。
- 移動・回転・拡大縮小・複製・削除、簡易建物の壁色、通りの長さを変更できます。最大240個、元に戻す操作は30回までです。
- 保存先はこのブラウザです。JSONの書き出し・読み込みで別の端末へ引き継げます。初期の街に戻す機能もあります。
- 保存した街は、次に「創作の世界」を開始したときに反映されます。読めない保存データは自動で上書きせず、初期の街と警告を表示します。
- 建物の配置・PZ・最高高度によって、飛行が成立しなくなる場合があります。編集画面で離陸地やターゲットとの重なりを警告します。

## 創作側のPZ・高度

この街のゲーム内飛行情報であり、現実のNOTAMや飛行許可ではありません。街の全域・プレイ中を通して適用します。高度は海抜（MSL）で比較し、計器には対地高度（AGL）も表示します。

| 設定 | ゲームでの扱い |
| --- | --- |
| 最高高度 | 初期値600m MSL。気球の上端まで含めて判定。編集画面で変更可能 |
| 赤PZ | 指定高度未満を禁止。上空を通過できる高度帯がある場合のみ通過 |
| 黄PZ | 離着陸・地上での取り扱いを禁止。上空通過自体は禁止しない |
| 青PZ | 指定高度を超える飛行を禁止 |

駅・タワー・提供ビルには赤PZ、お寺には黄PZが追従します。赤PZの境界高度は、種別の初期値（駅300m、タワー450m、ビル120m）と「地盤標高＋建物高さ＋80m」の高い方です。これは架空の街の設計ルールで、現実の建物種別からPZが決まるという意味ではありません。追加PZは円形で配置できます。

チームのパイロットは高度別の風と加熱・上昇の遅れを使って150秒先まで予測し、4秒ごとに飛行高度を検討します。判定用の気球の高さ28m・半径12mと高度の余裕を考慮します。水平方向は風で移動し、任意の方向へ旋回しません。PZ回避や高度変更を短い無線で知らせます。

通過できる高度・風が見つからなければフライトを終了し、禁止空域へ進めません。各移動区間でも侵入を検査します。周囲の5機にも制限を適用し、飛行できなくなった機体は表示を終了します。創作側ではクルーの観測報告によって予測用の風を更新し、高度と投下位置を再検討します。

PZの意味は [FAI AX Model Event Rules 2026 の7.3〜7.4](https://watchmefly.net/assets/uploads/enb/bbt2026_axmer2026.pdf) を参考にしています。

## 無線とマーカー回収ミッション

公開版の創作の世界では、ターゲット周囲100mは計測班の作業区域です。車は進入できず、車体の余裕を含めて中心から105mで止まります。橙色の境界で区域を示します。

| 行動 | 得点 |
| --- | ---: |
| ターゲットから100mより外、400m以内で停車して地上風を報告 | 50点（1回） |
| 投下を見届けて「投下確認」を送信 | 50点（1回） |
| 100m区域内への着地を確認して無線送信 | 回収成功と同じ1,000点 |
| 区域外で着地時に車が30m以内 | 1,000点 |
| 区域外で着地後に車が30m以内へ接近 | 500点 |

区域内のマーカーは計測班が計測・回収します。車は100mより外、400m以内で停車して着地確認を送ります。投下確認を逃しても着地確認は可能です。投下確認は落下中、投下地点から1,500m以内で停車して送れます。各確認は1回のみで、投下・着地確認の合計は1,050点です。

無線は条件を満たす場面だけ、左上の小さなカードで案内します。観測中は進み具合を、計測が完了したら確定した結果と送信ボタンを表示します。送信ボタンは実時間で5秒保持し、その間は他機の位置・高度・対象一覧や別の無線依頼で内容を入れ替えません。移動中もカードは残し、停車すると送信できます。送信または5秒経過で閉じ、未送信なら新たに観測します。観測時刻や残り秒数は表示・無線通知しません。報告済みの機体は、その観測範囲の対象一覧から外します。Cキーでもその場で送信でき、設定メニューは開きません。優先順位は依頼中の上空確認・PZの注意、投下確認、区域内着地確認、選択中の気球の上空風、地上風。複数の観測対象はカードの左右矢印で切り替えます。説明・得点・無線履歴は右上のメニューに収納。一時停止もメニュー内に置き、停止中だけ画面下に「再開」を表示します。

### 上空確認とPZへの注意

自分のチームのパイロットは、約200ft（60m）以上の大きな上昇を計画したときに上空確認を依頼します。離陸前だけでなく飛行中も対象です。クルーが停車すると小さな無線カード1枚で返答できます。返答待ちは現在の高度を保ちます。

- 上昇方向に他機がなければ「上空クリアです。」。送信を受けてから上昇します。
- 他機があれば「上空に赤の2号気球がいます。」のように最も近い1機の名前を自動表示し、送信後は上昇を待ちます。
- 他機が離れたら再確認を依頼します。送信直前にも状況を再確認し、以前表示されたクリアをそのまま採用しません。
- 依頼への返答は50点。「他機がいる」と伝えて待機につながった報告も対象です。同じ上昇依頼の再確認には重複加点しません。

ゲームでの上空判定は、自機の上方かつ予定上昇高度までの範囲（気球の高さ28mを含む）で水平50m以内にいる活動中の他機です。小さな高度修正には毎回の確認を要求しません。上昇中に他機が入ってきた場合は、上昇を控えて再確認します。

PZは内部で引き続き確認しますが、遠方PZの無線通知は今回は行いません。接近が予測され、対応を始める時期だけ共有します。開始時機は予想到達時間と必要な高度変更から決め、2m/sでの高度変更時間に、加熱の遅れ30秒、停車・返答45秒、余裕45秒を見込みます。既に通過できる高度なら通知を抑えます。赤PZの低空制限と青PZの高空制限を区別し、黄PZだけで上空通過を禁止しません。

クルー側も接近が予測された段階で、停車して「前方の〇〇PZに注意してください。」と伝えられます。PZの注意喚起も50点で、同じPZについて重複加点しません。上空確認と関係するPZは1枚のカードにまとめます。確認待ちのまま安全な通過が成立しなくなった場合は、禁止空域へ進入する前にフライトを終了します。

### 創作側の他機観測

- まずターゲットから100mより外、400m以内で停車して地上風を報告すると、他機の上空風観測を解放します。解放前の観測時間は引き継ぎません。
- 車がターゲットから200mより遠い時は「真下での観測」。他機から水平200m以内で停車し、5ゲーム秒観測します。
- 車がターゲットから200m以内では「ターゲット付近での観測」。他機から水平200m以内で停車し、3ゲーム秒観測します。100m作業区域への進入禁止は維持します。
- 各気球につき、それぞれの観測で1回ずつ報告できます。順番は自由で、3分待ち・300m移動の条件はありません。別の気球も続けて新たに観測できます。各報告は20点、後の動きとの照合で有益なら追加50〜100点です。変更後の自己ベストは旧ルールと分けて保存します。
- 気球は色・番号で選び、高度は海抜ft。位置の変化から風向・風速を推定します。30mを超える高度変化、車の移動、対象の消失・範囲外・再出現、車が200mの境界をまたいだ時は観測をやり直します。ただし計測完了後の実時間5秒保持中は、確定した観測の種類・データを維持します。
- 送信から20ゲーム秒後の別の移動区間と照合します。選ばれた高度の近くで、ターゲットへ向かう風の予測誤差が0.1m/s以上・20%以上改善した情報は追加50点、改善が0.5m/s以上なら追加100点。高度が不安定、消失、回避などで使えない場合は基本20点のみです。
- 観測・待ち時間・照合はゲーム内時計です。一時停止で止まり、時間加速に従います。

### 報告とパイロットの判断

創作側の実際の風には、事前のパイバルに加えて場所・高度・時間で滑らかに変化する小さな風の差を設けています。固定の式で再現でき、報告時に都合よく風を変える処理はありません。

パイロットの予測はパイバルから始め、観測の高さ・位置・鮮度・信頼度に応じて局所的に補正します。報告から高度差120m以上・距離1,500m以上では補正せず、180ゲーム秒で失効します。地上風は車の現在地点で観測し、低い層の補正に使います。上空風は高度候補にも追加し、同じ高度を維持する判断にも利用できます。

パイロットはマーカーの落下・風への追従を含む予想着地点と進入方向を評価します。投下は気球本体が400mに入った瞬間ではなく、予想着地点が近づき、その先で遠ざかる時機を選びます。報告による接近改善を保証するものではなく、PZ・最高高度・飛行性能を常に優先します。

制限時間は投下まで30分。投下後の確認・回収は時間切れ後も可能です。無線の短い表示と履歴で報告・判断・追加点を確認できます。新ルールの自己ベストは旧スコアと別に保存します。通常の気球操縦モードは従来の距離評価です。

携帯では描画密度を最大1.5倍、地形写真を最大1024px・詳細4区画に抑えます。タイルの取得・デコードは同時4件、20秒でタイムアウトし一度再試行します。詳細写真の一部が取得できなければ表示中の写真を維持し、60秒後から再試行できます。標高・初期写真の取得失敗はメニュー内に表示され、「再読み込み（最初から）」でやり直せます。iPhone実機の縞模様については、実機での改善確認が必要です。

## クラウドで開発

Node.js 24 と Python 3 を使います。

```sh
npm ci --ignore-scripts
npm run audit
npm test
npm run build
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

ブラウザ回帰テストは、Playwright・Pillow・Chromiumがある環境で `dist` をポート8001に配信し、`python3 tests/browser-smoke.py` と `python3 tests/browser-observation.py` を実行します。外部地形は固定画像で代替し、通常版の設定・離陸、不正な風の拒否、創作側の運転、街の編集画面、開発ページの非公開を確認します。PC・携帯の真上視点での運転、2つの観測範囲の報告枠、5秒保持・期限切れ・確定データ送信も検証します。実サービスの通信確認とは分けて扱います。

公開用の入口は `/game/prototype/` です。実際のデータの世界はエリア選択、フライト準備（風・開始時刻・離陸地点）、離陸の順に進みます。開始時刻は共有URLに保存しますが、飛行の風はパイバル設定を使います。住所検索は削除しています。旧共有URLのエリアと風も検証後に準備画面へ引き継ぎます。

共有URLは4096文字まで、風は32行まで（高度0〜30000ft、風向0〜360度、風速0〜150kt、高度重複不可）です。不正な共有値は警告して初期設定へ戻し、不正な編集値では離陸・共有できません。

Three.js はロックファイルで固定し、配布物へ同梱します。公開HTMLにはビルド時にCSPを設定し、スクリプトを同一サイトとハッシュの一致するインライン要素に限定します。地形・航空写真の通信先は国土地理院です。取得時間、受信量、画像サイズ、同時取得数を制限しています。

街の保存と検証・PZの高度判定・チームパイロットの予測飛行・観測の再送信・風の補正と追加点・投下/着地確認・得点・報告条件・投下予告・タイル取得処理のテストは、Node.js 24で `node --test tests/*.test.mjs` を実行します。
### 開発・実験機能

`game/development/play.html` は開発環境専用です。`npm run build` 後、別ポートでリポジトリをループバックへ配信して利用します。

```sh
python3 -m http.server 8002 --bind 127.0.0.1
```

`/game/development/play.html?dev=1` で気象・気圧配置などを検証できます。PLATEAU、道路クルー、実際のデータの世界のマーカー回収レースも開発版に残しています。開発版の外部データにも取得先・容量・時間・形式の検査を適用しています。

開発コードは `dist` に入りません。ソースを含むリポジトリ自体の公開・非公開はGitHubの設定で管理します。

### GitHub Pagesへの公開

**従来の「main のルートから公開」は使用しないでください。** 開発ページが配信されるため、変更を公開する前に Settings → Pages → Build and deployment → Source を **GitHub Actions** に切り替えます。

`.github/workflows/pages.yml` はpush・PR時にはテスト・依存関係監査・ビルドだけを行います。公開はコミットメッセージの先頭に `[publish]` を付けてmainへ反映するか、Actions → Validate and deploy public game → Run workflow で `main` を選んで明示的に実行してください。PagesのSourceがGitHub Actionsになっていることをワークフローでも確認し、`dist` だけを公開します。開発モジュールが公開コードの依存先に入った場合はビルドが失敗します。環境の自動セットアップ用の保存手順とは別の公開設定です。

将来対応のローカル検討資料は `.local-planning/` に置き、Git管理から除外します。
