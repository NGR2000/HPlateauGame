# 実際のデータと創作の世界

このプロジェクトでは、実際の地形を土台にした「創作の世界」を中心に開発します。
車で走る・気球から眺める体験から始め、建物を置いて街をつくる遊びへ育てます。
ゲーム名は未定です。

## 遊ぶ

[ホームを開く](https://ngr2000.github.io/HPlateauGame/)

- **実際のデータの世界**：これまでの気球ゲーム。エリア・風・開始時刻・離陸地点を選んで飛行します。実験機能は開発環境専用です。
- **創作の世界**：佐賀・嘉瀬川の既定エリア・風・出発地点を使うチェイスモード。車を操作し、チームのパイロットと周囲の5機が気球を飛ばします。

創作側は実地形を草地として表現した架空の街です。実在の街並みを再現するものではありません。
初期の街には、離陸広場からターゲットへ続く通り、住宅・店舗、駅前広場、公園、スポーツ施設を配置しています。通りの横には合流できる空間を残し、車は道を外れて自由に走れます。建物の本体には進入できません。
街の外縁には東京タワーと、増上寺の参考画像から着想した山門・参道・本堂を配置しています。チェイス競技では、気球（投下後はマーカー）が読み込み済みの地形範囲外へ出ると終了します。

車の操作：W/S または上下キーで加減速、A/D または左右キーでハンドル。両世界のチェイスモードはGameTargetに合わせ、Vで「進行方向／気球を見る」、Oで「俯瞰／運転に戻る」を切り替えます。以前のBキーも俯瞰に使えます。
創作側は自分のチームの離陸地点にある車の視点から始まります。自分のチームのパイロットが地上から離陸し、ほかの5機は上空を飛びます。
Oキーまたは「自分のチームを俯瞰」ボタンで、自分の気球とチェイスカーを収める範囲を見渡せます。他の5機は画角の自動調整には含めず、景色として飛びます。俯瞰中はホイール・ピンチで拡大縮小でき、引いて周囲の気球も眺められます。運転に戻ってから俯瞰を開き直すと、ズームを初期範囲へ戻します。Oで運転に戻ると見る方向を保ち、Vを押すと運転に戻って見る方向を切り替えます。
運転カメラは車の後方14m・高さ6mを基準に地面へ潜らないよう補正します。停車中はドラッグで見回し、ホイール・ピンチでズームできます。発進や視点切替で通常のカメラに戻ります。
チェイスモードのバーナー・排気音は車との距離（高度差を含む）で小さくなり、300m以上では聞こえません。創作側は他チームの気球も対象です。俯瞰に切り替えても、音を聞く位置は車のままです。
スマホ・タブレットでは、両方の世界のチェイスモードに前進・ブレーキ／後退・左右ハンドルのタッチボタンが表示されます。前進とハンドルは同時に長押しできます。指を離すと入力が解除され、アクセルを離した車は自然減速します。
景色を広く見せるため、普段は左右下の半透明の運転ボタンと右上の「☰ メニュー」だけを表示します。視点・俯瞰・一時停止・計器・世界名・ホームへの移動はメニュー内にまとめています。視点を選ぶとメニューは自動で閉じます。

創作側の1号車には、提供されたBlenderモデル `sky_chase_car.blend` を使用します。
自分のチームの気球は提供モデル `MV56b_hot_air_balloon.blend` を使用します。俯瞰のときだけ水色の「気球」と黄色の「車」の名札が付きます。運転中・気球を見る視点では名札と補助線を隠します。名札はスマホ・PCや視点の距離によらず一定の小さいサイズで表示します。
ほかの5機は色と巡航高度を変えています。回収・スコアの対象は従来どおり自分のチームのマーカーです。
一時停止と時間加速は全機に反映します。
元データとブラウザ用GLB、再変換手順は [提供アセット](game/prototype/assets/README.md) に保存しています。

## 街を作り変える

ホームの主要ボタンは従来どおりです。「創作の世界」の下の小さな「街を作り変える」リンクから編集画面を開きます。

- 提供された東京駅・東京タワー・スポーツ施設・ビルと、住宅・店舗・倉庫・お寺・公園・広場・通り・木を配置できます。
- 移動・回転・拡大縮小・複製・削除、簡易建物の壁色、通りの長さを変更できます。最大240個、元に戻す操作は30回までです。
- 保存先はこのブラウザです。JSONの書き出し・読み込みで別の端末へ引き継げます。初期の街に戻す機能もあります。
- 保存した街は、次に「創作の世界」を開始したときに反映されます。読めない保存データは自動で上書きせず、初期の街と警告を表示します。
- 建物の配置・PZ・最高高度によって、飛行が成立しなくなる場合があります。編集画面で離陸地やターゲットとの重なりを警告します。

## 創作側のPZ・高度

この街のゲーム内飛行情報であり、現実のNOTAMや飛行許可ではありません。街の全域・プレイ中を通して適用します。高度は海抜（MSL）で比較し、計器には対地高度（AGL）も表示します。

| 設定 | ゲームでの扱い |
| --- | --- |
| 最高高度 | 初期値600m MSL。気球の上端まで含めて判定。編集画面で変更可能 |
| 赤PZ | 指定高度未満を禁止。上空を通過できる高度帯がある場合のみ通過 |
| 黄PZ | 離着陸・地上での取り扱いを禁止。上空通過自体は禁止しない |
| 青PZ | 指定高度を超える飛行を禁止 |

駅・タワー・提供ビルには赤PZ、お寺には黄PZが追従します。赤PZの境界高度は、種別の初期値（駅300m、タワー450m、ビル120m）と「地盤標高＋建物高さ＋80m」の高い方です。これは架空の街の設計ルールで、現実の建物種別からPZが決まるという意味ではありません。追加PZは円形で配置できます。

チームのパイロットは高度別の風と加熱・上昇の遅れを使って150秒先まで予測し、4秒ごとに飛行高度を検討します。判定用の気球の高さ28m・半径12mと高度の余裕を考慮します。水平方向は風で移動し、任意の方向へ旋回しません。PZ回避や高度変更を短い無線で知らせます。

通過できる高度・風が見つからなければフライトを終了し、禁止空域へ進めません。各移動区間でも侵入を検査します。周囲の5機にも制限を適用し、飛行できなくなった機体は表示を終了します。地上クルーの報告で飛行判断が変わる機能は今回の対象外です。

PZの意味は [FAI AX Model Event Rules 2026 の7.3〜7.4](https://watchmefly.net/assets/uploads/enb/bbt2026_axmer2026.pdf) を参考にしています。

## マーカー回収ミッション

両世界のチェイスモードに、GameTargetを参考にした無線と回収得点を実装しています。

- ターゲットから水平距離100〜400mの場所で停車すると「地上風を報告」が表示されます。ボタンまたはCキーで送信し、1回だけ50点。報告するのはゲーム内のターゲット地点の地上風です。
- チームのパイロットがマーカーを投下します。現在の風で投下範囲まで60秒以内と予測したときに、文字の無線で予告します。予測はゲーム内時間で、風や飛行高度によって変わります。
- マーカー着地時、車が水平距離30m以内なら1,000点。間に合わなければ競技を続け、着地後に30m以内へ近づくと500点です。未回収時はマーカーまでの距離・方位を画面に表示します。
- 投下の制限時間は30分。投下済みなら時間切れ後も回収できます。未投下で時間切れになると、獲得済みの報告点だけで終了します。
- 無線は8秒で消えます。「回収ミッション」を開くと、得点・ルール・無線の記録を確認できます。結果の自己ベストはブラウザに保存します。

地上風報告はパイロットとの連携を表す得点イベントで、パイロットの風判断や進路は変更しません。道路走行の加点は未実装です。通常の気球モードは従来どおりターゲットからの距離で評価します。

携帯では描画密度を最大1.5倍、地形写真を最大1024px・詳細4区画に抑えます。タイルの取得・デコードは同時4件、20秒でタイムアウトし一度再試行します。詳細写真の一部が取得できなければ表示中の写真を維持し、60秒後から再試行できます。標高・初期写真の取得失敗はメニュー内に表示され、「再読み込み（最初から）」でやり直せます。iPhone実機の縞模様については、実機での改善確認が必要です。

## クラウドで開発

Node.js 24 と Python 3 を使います。

```sh
npm ci --ignore-scripts
npm run audit
npm test
npm run build
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

ブラウザ回帰テストは、Playwright・Pillow・Chromiumがある環境で `dist` をポート8001に配信し、`python3 tests/browser-smoke.py` を実行します。外部地形は固定画像で代替し、通常版の設定・離陸、不正な風の拒否、創作側の運転、街の編集画面、開発ページの非公開を確認します。実サービスの通信確認とは分けて扱います。

公開用の入口は `/game/prototype/` です。実際のデータの世界はエリア選択、フライト準備（風・開始時刻・離陸地点）、離陸の順に進みます。開始時刻は共有URLに保存しますが、飛行の風はパイバル設定を使います。住所検索は削除しています。旧共有URLのエリアと風も検証後に準備画面へ引き継ぎます。

共有URLは4096文字まで、風は32行まで（高度0〜30000ft、風向0〜360度、風速0〜150kt、高度重複不可）です。不正な共有値は警告して初期設定へ戻し、不正な編集値では離陸・共有できません。

Three.js はロックファイルで固定し、配布物へ同梱します。公開HTMLにはビルド時にCSPを設定し、スクリプトを同一サイトとハッシュの一致するインライン要素に限定します。地形・航空写真の通信先は国土地理院です。取得時間、受信量、画像サイズ、同時取得数を制限しています。

### 開発・実験機能

`game/development/play.html` は開発環境専用です。`npm run build` 後、別ポートでリポジトリをループバックへ配信して利用します。

```sh
python3 -m http.server 8002 --bind 127.0.0.1
```

`/game/development/play.html?dev=1` で気象・気圧配置などを検証できます。PLATEAU、道路クルー、実際のデータの世界のマーカー回収レースも開発版に残しています。開発版の外部データにも取得先・容量・時間・形式の検査を適用しています。

開発コードは `dist` に入りません。ソースを含むリポジトリ自体の公開・非公開はGitHubの設定で管理します。

### GitHub Pagesへの公開

**従来の「main のルートから公開」は使用しないでください。** 開発ページが配信されるため、変更を公開する前に Settings → Pages → Build and deployment → Source を **GitHub Actions** に切り替えます。

`.github/workflows/pages.yml` はpush・PR時にはテスト・依存関係監査・ビルドだけを行います。公開は Actions → Validate and deploy public game → Run workflow で `main` を選んで明示的に実行してください。PagesのSourceがGitHub Actionsになっていることをワークフローでも確認し、`dist` だけを公開します。開発モジュールが公開コードの依存先に入った場合はビルドが失敗します。環境の自動セットアップ用の保存手順とは別の公開設定です。

将来対応のローカル検討資料は `.local-planning/` に置き、Git管理から除外します。
